# Generating Domain Models with `@freezed`

This guide covers how to create immutable domain models using the [Freezed](https://pub.dev/packages/freezed) package in a Flutter project codebase.

## Required Dependencies

### Runtime dependency (in `pubspec.yaml`)

```yaml
dependencies:
  freezed_annotation: ^3.1.0
```

### Dev dependencies (for code generation)

```yaml
dev_dependencies:
  build_runner: ^2.10.4
  freezed: ^3.2.3
  json_serializable: ^6.11.1
```

> In a monorepo setup, `build_runner`, `freezed`, and `json_serializable` are typically configured in the workspace `pubspec.yaml` files. You typically only need `freezed_annotation` as a direct dependency.

## Code Generation Commands

After creating or modifying a freezed model:

```bash
# From the project root
make generate

# Or directly with FVM
cd my_app && fvm dart run build_runner build --delete-conflicting-outputs
```

> **Never edit generated files** (`*.g.dart`, `*.freezed.dart`) manually.

## File Structure

Every freezed model file follows this pattern:

```dart
import 'package:freezed_annotation/freezed_annotation.dart';

part 'my_model.freezed.dart';   // Generated: copyWith, ==, hashCode, toString
part 'my_model.g.dart';         // Generated: fromJson/toJson

@freezed
abstract class MyModel with _$MyModel {
  const factory MyModel({
    required String id,
  }) = _MyModel;

  factory MyModel.fromJson(Map<String, dynamic> json) =>
      _$MyModelFromJson(json);
}
```

The two `part` directives are mandatory:

- `.freezed.dart` — generated by `freezed`, contains `copyWith`, equality operators, `toString`
- `.g.dart` — generated by `json_serializable`, contains `fromJson`/`toJson`

## Test File Location

Tests mirror the `lib/` structure:

```
lib/src/features/notifications/domain/app_notification.dart
test/src/features/notifications/domain/app_notification_test.dart
```

## Example 1: Simple Model with Enum

A minimal model with required fields and an associated enum.

**File:** `lib/src/features/authentication/domain/app_user.dart`

```dart
import 'package:freezed_annotation/freezed_annotation.dart';

part 'app_user.freezed.dart';
part 'app_user.g.dart';

@freezed
abstract class AppUser with _$AppUser {
  const factory AppUser({
    required String uid,
    required AppUserType userType,
  }) = _AppUser;

  factory AppUser.fromJson(Map<String, dynamic> json) =>
      _$AppUserFromJson(json);
}

enum AppUserType { consumer, producer }
```

### What you get for free

```dart
// Create
final user = AppUser(uid: '123', userType: AppUserType.producer);

// Immutable copy
final updated = user.copyWith(userType: AppUserType.consumer);

// Equality (value-based, not reference-based)
AppUser(uid: '123', userType: AppUserType.producer) ==
    AppUser(uid: '123', userType: AppUserType.producer); // true

// Serialization
final json = user.toJson(); // {'uid': '123', 'userType': 'producer'}
final fromJson = AppUser.fromJson(json);
```

## Example 2: Model with Custom Serializers, Optional Fields, and Multiple Enums

A more complex model using custom serializers for Firestore `Timestamp` fields and multiple enums.

**File:** `lib/src/features/notifications/domain/app_notification.dart`

```dart
import 'package:my_app/src/core/utils/freezed_custom_serializers.dart';
import 'package:freezed_annotation/freezed_annotation.dart';

part 'app_notification.freezed.dart';
part 'app_notification.g.dart';

@freezed
abstract class AppNotification with _$AppNotification {
  const factory AppNotification({
    required String id,
    required String userId,
    required AppNotificationType type,
    required String entityId,
    required String content,
    required AppNotificationStatus status,
    @TimestampSerializer() required DateTime sendDate,
    @TimestampSerializer() DateTime? expireAt,
    String? companyId,
  }) = _AppNotification;

  factory AppNotification.fromJson(Map<String, dynamic> json) =>
      _$AppNotificationFromJson(json);
}

enum AppNotificationType {
  bid,
  quote,
  newQuote,
  task,
  message,
  quoteCancelled,
  confirmedTaskExecution,
  disputedTaskExecution,
  completedTaskExecution,
  cancelledServiceRequest,
  paymentFailed,
  paymentExpired,
  serviceAboutToStart,
  serviceStartsToday,
  serviceEndsToday,
  serviceDelayYesterday,
  interestConfirmationCheck,
}

enum AppNotificationStatus { unread, read }
```

### Key patterns

- **`@TimestampSerializer()`** — Annotates `DateTime` fields that come from Firestore as `Timestamp` objects. The custom serializer handles the conversion.
- **Optional fields** — Use `Type?` syntax (e.g., `DateTime? expireAt`, `String? companyId`). These default to `null`.
- **Multiple enums** — Define enums in the same file when they are tightly coupled to the model.

### Writing a Custom Serializer

```dart
class TimestampSerializer implements JsonConverter<DateTime, dynamic> {
  const TimestampSerializer();

  @override
  DateTime fromJson(dynamic json) {
    if (json is Timestamp) return json.toDate();
    if (json is String) return DateTime.parse(json);
    throw ArgumentError('Cannot convert $json to DateTime');
  }

  @override
  dynamic toJson(DateTime date) => Timestamp.fromDate(date);
}
```

## Example 3: Model with Defaults, Custom Methods, and Nested Types

A domain model with `@Default` values, a private constructor for custom getters/methods, nested model types, and a custom enum serializer.

**File:** `lib/src/domain/bid/app_bid_installment.dart`

```dart
import 'package:freezed_annotation/freezed_annotation.dart';
import 'package:core/src/serializers/firestore_timestamp_serializer.dart';

part 'app_bid_installment.freezed.dart';
part 'app_bid_installment.g.dart';

@freezed
abstract class AppBidInstallment with _$AppBidInstallment {
  const factory AppBidInstallment({
    required String id,

    @Default(AppBidInstallmentType.milestone)
    @_InstallmentTypeSerializer()
    AppBidInstallmentType type,

    required int amount,

    @Default(AppBidInstallmentStatus.pending)
    @_InstallmentStatusSerializer()
    AppBidInstallmentStatus status,

    String? orderId,
    String? transactionId,
    String? chargebackReasonCode,

    @NullableFirestoreTimestampSerializer() DateTime? createdAt,
    @NullableFirestoreTimestampSerializer() DateTime? updatedAt,
  }) = _AppBidInstallment;

  // Required for custom getters/methods
  const AppBidInstallment._();

  factory AppBidInstallment.fromJson(Map<String, dynamic> json) =>
      _$AppBidInstallmentFromJson(json);

  // Custom getters
  bool get isMilestone => type == AppBidInstallmentType.milestone;
  bool get isExtra => type == AppBidInstallmentType.extra;
  bool get isRefund => type == AppBidInstallmentType.refund;
  int get absoluteAmount => amount.abs();
  bool get hasFailed => status == AppBidInstallmentStatus.failed;
}
```

### Key patterns

- **`@Default(value)`** — Provides a default value, making the field optional in the constructor:
  ```dart
  // Both are valid:
  AppBidInstallment(id: '1', amount: 5000);
  AppBidInstallment(id: '1', amount: 5000, type: AppBidInstallmentType.extra);
  ```
- **Private constructor `const AppBidInstallment._();`** — Required when you add custom getters or methods to the class. Without this line, Dart won't let you define instance members.
- **Custom enum serializer** — Use `JsonConverter<EnumType, String>` when the backend uses different string values than the Dart enum names.
- **`@NullableFirestoreTimestampSerializer()`** — Variant of the timestamp serializer that handles `null` values.

## Quick Reference: When to Use What

| Pattern                        | When to use                        |
| ------------------------------ | ---------------------------------- |
| `required Type field`          | Field must always be provided      |
| `Type? field`                  | Optional field, defaults to `null` |
| `@Default(value) Type field`   | Optional with an explicit default  |
| `@SomeSerializer() Type field` | Custom JSON conversion needed      |
| `const MyModel._();`           | You need custom getters or methods |
| Enum in same file              | Enum is tightly coupled to model   |
| Enum in separate file          | Enum is shared across models       |

## Common Mistakes

| Mistake                                    | Fix                                                            |
| ------------------------------------------ | -------------------------------------------------------------- |
| Editing `*.g.dart` or `*.freezed.dart`     | Run `make generate` instead                                    |
| Missing `part` directives                  | Add both `part 'file.freezed.dart';` and `part 'file.g.dart';` |
| Custom getters without private constructor | Add `const MyModel._();` before the getters                    |
| Forgetting to run code gen after changes   | Always run `make generate` after modifying models              |
| Placing shared models in app module        | Check if it belongs in the shared `core` package               |
